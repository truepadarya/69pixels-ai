# Управление первым экраном наклоном телефона

На телефоне освещение портрета реагирует на наклон устройства. Первое корректное показание задаёт исходное положение; движение сглаживается, диапазон ограничен. Поворот экрана учитывается при выборе осей.

Если браузер требует разрешение, появляется кнопка **Enable tilt motion**. Запрос запускается непосредственно её нажатием, после ответа кнопка скрывается. При отказе, отсутствии датчика или корректных показаний остаётся прежняя автоматическая анимация. При уменьшении движения, уходе с первого экрана и потере фокуса обработка наклонов останавливается.

Доступ к ориентации устройства требует защищённого контекста: для просмотра с телефона используйте HTTPS. Требования API: [Device Orientation and Motion](https://www.w3.org/TR/orientation-event/).

Изменены только `PointillistHero.astro` и его существующий скрипт `public/pointillist/turn.js`; обработка мыши на десктопе сохранена.

Проверки:

- `node audit/hero-gyro.test.mjs`: доступ только после реального нажатия, отказ и ошибка разрешения, отсутствие API и пустые показания, обе оси наклона, остановка автоматического цикла после показаний, скрытый первый экран, reduced motion, горизонтальный телефон, мышь на десктопе и очистка обработчиков при навигации.
- `npm.cmd run check`: 0 ошибок, 0 предупреждений, 0 подсказок.
- `npm.cmd run build`: успешная сборка 5 страниц.

Проверено в Chromium с эмуляцией размеров, ориентации и состояний разрешения. Физический телефон и нативный Safari в этой среде не проверялись.
